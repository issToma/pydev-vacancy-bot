# vacancy_bot

Telegram-бот для поиска и аналитики вакансий с hh.ru. Скрапер на Playwright собирает
вакансии в PostgreSQL; бот даёт по ним поиск с фильтрами, статистику зарплат, подписки
с уведомлениями, подбор по резюме через LLM и ответы на вопросы по программированию.

## Возможности

| Команда | Что делает |
|---|---|
| `/vacancies` | поиск вакансий по разработке |
| `/filter` | фильтры кнопками: страна, удалёнка, аккредитованные IT-компании |
| `/stack` | топ востребованных технологий |
| `/salaries` | средняя и медианная зарплата по грейдам |
| `/subscribe`, `/subscriptions` | подписка на новые вакансии по условиям и список своих подписок |
| `/match` | подбор вакансий по тексту резюме (LLM, retrieve-then-rank) |
| `/ask`, `/usage` | вопрос по программированию со стримингом ответа и памятью диалога; свой расход токенов |

Навигация — reply-клавиатурой: `/start` открывает кнопки-действия («🔎 Поиск»,
«📊 Топ стек», «🎯 Подбор по резюме», «🤖 Спросить у ИИ» …), команды продолжают работать
и по вводу. Наборы кнопок и команд собираются из реестра сервисов, поэтому новый сервис
добавляется одной строкой в `bot/registry.py`, без правок ядра.

## Стек

Python 3.13 · uv · aiogram 3 · FastAPI · SQLAlchemy 2.0 (async, asyncpg) + Alembic ·
Celery + Beat · RabbitMQ (aio-pika) · Redis · Playwright · LLM через OpenAI-совместимый
API (по умолчанию Google Gemini).

## Архитектура

```
Telegram ──► aiogram-бот ─┬─► RabbitMQ ──► Celery-воркер ─┬─ scrape (Playwright) ──► PostgreSQL
                          │         ▲                     └─ match (ранжирование LLM)
                          │         └── Beat: scrape по расписанию
                          ├─► LLM напрямую, стримингом (/ask, минуя Celery)
                          └─◄ RabbitMQ: consumer уведомлений внутри бота, сбой → DLQ

FastAPI ──► те же сервисы по REST (+ Swagger), поднимается отдельно
```

- Долгое и блокирующее (скрапинг, ранжирование резюме) уходит в Celery; интерактивный
  `/ask` идёт прямым async-стримингом, чтобы ответ начинал печататься сразу.
- RabbitMQ используется не только как брокер Celery: уведомления о новых вакансиях
  публикуются в отдельную очередь, бот читает её напрямую, недоставленное уходит в DLQ.
- Сервис реализует контракт `ServiceModule` — телеграм-роутер, REST-роутер и метаданные
  меню; инфраструктура раздаётся хендлерам объектом `Infra`, ядро о конкретных сервисах
  не знает.
- Скрапер пишет в собственную таблицу `vacancies_scraped`, дедупликация — по id вакансии.

## Быстрый старт

Нужны [uv](https://docs.astral.sh/uv/) и Docker.

```bash
uv sync
cp -n .env.example .env          # заполнить TELEGRAM_BOT_TOKEN и LLM_API_KEY
./run.sh                         # инфраструктура, миграции, бот и воркер
```

Логи идут в текущий терминал, Ctrl+C останавливает бота и воркер. `./stop.sh` гасит
всё, включая контейнеры.

Пошагово, если нужно по отдельности:

```bash
docker compose up -d --wait postgres redis rabbitmq
uv run alembic upgrade head
uv run python -m bot.main                                                      # бот
uv run celery -A core.celery_app:celery_app worker -B -l info -n vacancy@%h    # воркер + Beat
```

REST-слой для работы бота не нужен — бот обращается к инфраструктуре напрямую. Поднять
его отдельно, Swagger на http://127.0.0.1:8000/docs:

```bash
uv run uvicorn api.main:app --reload
```

Контейнеры инфраструктуры намеренно собраны под общим именем compose-проекта `infra`,
чтобы несколько проектов пользовались одними Postgres, Redis и RabbitMQ. Следствие:
`docker compose down` удалит контейнеры всего проекта вместе с соседними, поэтому
для остановки используется `./stop.sh`.

## Конфигурация

Все настройки — переменные окружения (`pydantic-settings`), каждая описана в
[`.env.example`](.env.example). Обязательны только `TELEGRAM_BOT_TOKEN` и `LLM_API_KEY`
(бесплатный ключ выдаёт Google AI Studio), у остальных рабочие дефолты под локальный
compose. Без `LLM_API_KEY` `/ask` и `/match` отвечают «LLM не настроен», остальное работает.

Один токен — один процесс: Telegram отдаёт long polling только одному экземпляру,
второй получит `409 Conflict`. Скрапингу hh.ru нужен российский IP, иначе сайт отдаёт
заглушку вместо выдачи.

## Запуск не на localhost

Дефолты рассчитаны на одну машину в доверенной сети. Для любого другого окружения
требуется:

1. Задать `ALLOWED_USER_IDS` — Telegram-id, которым разрешён бот. Пустое значение
   пускает всех, а `/ask` и `/match` тратят квоту LLM. `AllowlistMiddleware` стоит
   первым в цепочке, до rate-limit.
2. Закрыть порты инфраструктуры: `docker-compose.yml` публикует Postgres, Redis и
   RabbitMQ на всех интерфейсах с паролями-заглушками — нужен префикс `127.0.0.1:`
   и собственные пароли. Правила публикации docker пишет в `nat/DOCKER` мимо `INPUT`,
   поэтому ufw такие порты не закрывает.
3. Не выставлять REST-слой наружу: у него открыт Swagger и `POST /subscriptions`
   без авторизации.

## Разработка

```bash
uv run pytest                                        # живые сервисы не нужны
uv run alembic revision --autogenerate -m "msg"      # миграция по моделям
uv run alembic upgrade head
```

Тесты покрывают контракт реестра и навигацию, рендер Telegram-HTML, матчинг подписок,
rate-limit на фейковом Redis, дедупликацию скрапера, статистику зарплат, хелперы `/match`
и `GET /health`. GitHub Actions прогоняет их на каждый push и pull request.

## Структура

```
bot/         aiogram: диспетчер и polling, реестр сервисов, middlewares, навигация, /help
api/         FastAPI: /health и REST-роутеры сервисов из реестра
core/        конфиг, контракты (Infra/ServiceModule), БД, Redis, Celery, LLM-клиент, модели
services/    vacancy/: скрапер hh.ru, поиск, фильтры, подписки, зарплаты, /match, /ask
migrations/  Alembic
tests/       pytest
```
